04 / Latency, reliability & energy

更快开始，不一定更快生成。

AtomSGLang

P90 首 token 延迟

秒 · 越低越好

并发采用 log₂ 刻度；虚线表示跨配置边界。受上方“只看共同 conc”筛选影响。

请求成功率：整体随并发升高而下降

Atom 从 c1 的 94.91% 降至 c256 的 79.97%；SGLang 从 c1 的 94.86% 降至 c160 的 81.98%。共同 c64 / c96 / c128 的成功率差异（SGLang−Atom）为 +0.06 / −0.28 / −1.04 个百分点。

高并发：SGLang 首 token 更快，生成更慢

Atom c64 / c96 的 P90 TTFT 约为 16.7 秒，c128 为 17.55 秒。SGLang 对应为 9.19 / 13.59 / 17.28 秒；但其 TPOT 与 Interactivity 更弱，c128 的 TTFT 优势也已很小。

能效：共同高并发点，SGLang 的 J/token 更低

以下能耗为输入 + 输出 token 口径，保留原文能效表的 6 位小数。条形从零开始，同一比例尺，越短越好。

07 / What to choose

目标不同，答案也不同。

结论只适用于本次 sweep
低并发 · 单 chip 效率
SGLang TP4

c1 / c4 / c8 的每 chip 吞吐更高，但不能把这一优势等同于整机吞吐优势。

同配置附近 · 中等并发
SGLang @ c16

本次最接近同配置的点，同时改善了每 chip 吞吐与 P90 用户交互速度。

高并发 · 吞吐与持续生成
Atom TP8 + DPA

共同 c64 / c96 / c128 更强；需要同时考虑其与 SGLang 在 KV offload 上的差异。

高并发 · TTFT 与能效
SGLang + DRAM HiCache

首 token 延迟与能效有一定优势，代价是更弱的 P90 TPOT 和 Interactivity。

Next experiment / 严格框架 A/B

固定同一组 TP、DPA、KV offload、conc、image 基础版本和 runner，至少补齐 TP8、无 offload 的 conc=1/4/8/16/32/48/64/96/128，再判断框架本身带来的差异。
