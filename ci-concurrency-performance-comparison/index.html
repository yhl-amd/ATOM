Lab notes / 2026.09.07 · 后续受控实验

两个实验：一个拆分工作，一个替换配置。

已完成 · GPU0 / GPU4 · 不覆盖原 CI 结果

这不是又跑了两次“ATOM 对 SGLang”整模型测试。两次都是在同一个 ATOM 环境里，拿原路径 A 对比只改一个局部的候选 B：先确认输出，再测 GPU 时间。我们想区分“trace 看起来慢”与“这个改法真的能提速”。

01 / Attention reduction

把 512 维输出分给更多线程块

核心两阶段快约 0.8%–2.6%

只改最终合并的工作分配，不换 Attention 主 kernel。是小收益，不是原 trace 中近两倍差距的解法。

口径：KV=640，ASM＋reduction，同输入热回放；不是整模型 TPOT。

02 / Routed MoE dispatch

保留权重，借用另一组 kernel 配置

有快有慢，不能全局替换

T=16 分散路由快约 6%；T=8 慢约 5%，T=12 慢 4.6%–14.2%。新增中间激活量化会吃掉部分收益。

口径：完整 routed MoE；不含 shared expert、通信及模型其他部分。

T

T=8 / 12 / 16 是一次算子调用实际处理的 token 行数，不是客户端并发 c8 / c12 / c16。实验背景是 c16 的 speculative verify 路径。T=12 会查 M=16 的调优档，但实验里仍只计算实际 12 行，并未补成 16 行。

Experiment 01 / 改工作分配，不改计算内容

Attention：512 维仍然全算，只是不再交给同一个 CTA。

Attention 主阶段先计算多个 KV 分片的中间结果，reduction 再把它们合并成最终输出。此前怀疑小 batch 时线程块太少，GPU 没铺满；这次只验证“沿输出维 D 拆开，增加并行度”这一条线索。CTA 可以理解为 GPU 的一个线程块。

固定了什么

同一镜像、同一 GPU 上配对；相同输入、FP8/BF16 布局、head 数、split 数与 sink。只在隔离副本中修改 reduction；没有替换成 SGLang 的整套 Attention。

怎么测

先测独立 reduction，再测真实 ASM → reduction。T=8/12/16、不同 KV 长度；graph 串联 61 次调用，预热后交替 A/B，用 GPU events 计时，输入量化不计入。

结果怎么理解：多拆 CTA 确实能省一点时间，但完整两阶段的收益很小。这个实验没有改 split 维逐步合并的算法，也没改 ASM 主阶段，因此不能据此说已经解决 Attention 慢的根因。

独立 reduction、退化场景与数值检查
  • KV=640、61 份独立 partial buffers 时，独立 reduction 降低约 3.8%–5.9%；但热复用同一 buffer、T=12/16 时有约 0.6%–1.0% 退化。不能只展示最好点。
  • 两张卡各做 20 组数值检查：各 18 组逐值一致；每卡 2,842,624 个被比较值里有 2 个不同，最大绝对差 0.00048828125。通过 BF16 误差界、FP64 参考、LSE 和输出 guard 检查，并非全覆盖 bitwise pass。
  • 首轮严格比较失败日志保留；后续实际 ASM＋reduction 两卡共 6 个形状点的输出均逐值一致。零 KV padding 行与有效请求分开检查，不拿原有 NaN padding 当有效输出通过。
  • 开关为 AITER_V4_REDUCE_D_SPLIT，默认关闭；本次只测试隔离副本，没有修改正式镜像或默认服务配置。
Experiment 02 / 不重量化权重，改变 routed kernel 配置

MoE：换的是 tile 与中间输出组织，不是模型权重。

用户的约束是“不把 FP8 shared expert 再量化成 FP4”。所以这次保留 routed 的 FP4 权重、384 个 expert、top-k=6；只借用 SGLang 对应调优行的 kernel 配置，重新应用到 384/6 的形状。shared expert 没有加载、没有改权重，也没有纳入计时。

固定了什么

hidden=7168、TP8 shard intermediate=384、E=384、top-k=6、Silu、limit=10、GU interleave。A/B 共用一次构造的 packed FP4 权重、scale、BF16 输入和路由；不读取或转换 checkpoint 权重。

Interpretation / 已证实与下一步分开

两个小实验，不能相加成“整模型快了 8%”。

原 CI 的 P90 TPOT 是 17.65 → 14.42 ms/token，打平需要 ATOM 降低约 18.3%。而本节测的是单次 Attention 核心两阶段和 routed MoE，不包含完整 decode、MTP、shared expert、通信及调度；两项比例的分母不同，也没有做组合后的整模型 A/B。

现在可以下的结论

D-split 是小幅候选优化，不是 Attention 差距的完整解释。MoE 搬配置有明确反例，不能全局开启。两项都没有通过新增权重量化来“换性能”。

现在不能下的结论

不能称为“已打平 SGLang”；不能把3 μs的 profiler 数值或每层收益直接乘61当TPOT；不能认为 shared fusion、AITER 版本及多 stream 竞争已被排除。

  1. 建议下一步：MTP step0 graph 化的可切换 A/B。先以无 profiler / 低扰动计时复核完整生成轮次与跨 rank 提交；保证 KV、索引、输出和每轮产出 token 语义不变。此项尚未在这两个实验中执行。
  2. 再看完整 Attention 路径。固定输入、KV内容和精度，评估主阶段与 split 归约组织，而不是只继续增加 D 维 CTA。原 SGLang trace 使用 BF16 KV，不能直接冒充同精度对照。
  3. MoE 只补测有针对性的组合。候选 tile ＋保留融合 FP8 中间输出，尝试避免新增量化开销；之后连同 FP8 shared 分支并发测完整 FFN。它是待验证假设，不是已实现收益。

此前单独增加 graph capture 档位也未证明稳定整体提升；prefill 短尾仍有成本，但不能解释已剔除 prefill 的稳定 decode 差距。后续真实请求验证还要守住 TTFT、吞吐、正确性与稳定性，不能只看某个更快的 kernel。

04 / Latency, reliability & energy

更快开始，不一定更快生成。

AtomSGLang

P90 首 token 延迟

秒 · 越低越好

并发采用 log₂ 刻度；虚线表示跨配置边界。受上方“只看共同 conc”筛选影响。

请求成功率：整体随并发升高而下降

Atom 从 c1 的 94.91% 降至 c256 的 79.97%；SGLang 从 c1 的 94.86% 降至 c160 的 81.98%。共同 c64 / c96 / c128 的成功率差异（SGLang−Atom）为 +0.06 / −0.28 / −1.04 个百分点。

高并发：SGLang 首 token 更快，生成更慢

Atom c64 / c96 的 P90 TTFT 约为 16.7 秒，c128 为 17.55 秒。SGLang 对应为 9.19 / 13.59 / 17.28 秒；但其 TPOT 与 Interactivity 更弱，c128 的 TTFT 优势也已很小。

07 / What to choose

目标不同，答案也不同。

结论只适用于本次 sweep
低并发 · 单 chip 效率
SGLang TP4

c1 / c4 / c8 的每 chip 吞吐更高，但不能把这一优势等同于整机吞吐优势。

同配置附近 · 中等并发
SGLang @ c16

本次最接近同配置的点，同时改善了每 chip 吞吐与 P90 用户交互速度。

高并发 · 吞吐与持续生成
Atom TP8 + DPA

共同 c64 / c96 / c128 更强；需要同时考虑其与 SGLang 在 KV offload 上的差异。

高并发 · TTFT 与能效
SGLang + DRAM HiCache

首 token 延迟与能效有一定优势，代价是更弱的 P90 TPOT 和 Interactivity。
