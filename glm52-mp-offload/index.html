03

把“打包在一起”说清楚

Q1Worker 会先把两份 cache 打包再发吗？

Worker 注册各层的 view() 及 GPU IPC 句柄，提交范围和块号。实际 gather / scatter 由 server 驱动，不同布局的数据在那里进入同一对象的对应区域。

Q2能只读回 MLA，先不读回 indexer 吗？

当前这条 connector 路径没有这样的独立策略。请求覆盖已经注册的整组缓存，两类数据共同保存、共同恢复。不能把一个 kernel group 的完成等同于整个 chunk 已恢复。

Q3同一个对象，就只有一次拷贝吗？

对象数量与拷贝次数是两回事。不同布局仍需各自的 kernel 处理，还可能涉及暂存、批处理及主机与设备间传输；这里不把“一起存”解释为“一次 DMA”。

Q4是不是每层都有一份 indexer cache？

只有拥有 indexer 的层分配对应缓存；GLM-5.2 的共享层不因此额外拥有一份。图中省略 L1 的 indexer 只是说明这一点，实际层映射由模型配置决定。
